MAVLink Generator

发表于2026-08-18|更新于2026-08-18|技术博客
|总字数:2.1k|阅读时长:8分钟|浏览量:

基于 pymavlink 官方代码生成工具链（mavgen）定制的 MAVLink 协议 C/C++ 代码生成项目。通过 XML 消息定义文件，自动生成消息结构体、序列化/反序列化函数、CRC 校验表与解析器，用于嵌入式设备等与上位机之间的 MAVLink 2.0 通信。

生成的代码为纯头文件实现，无需链接任何库，适合资源受限的嵌入式系统；C++11 实现在 C 实现之上提供更现代的类型安全接口。

**项目链接：**https://github.com/lixiaodao1234/mavlink_generator.git

目录结构

环境要求

  • Linux（Ubuntu 22.04 验证通过）
  • Python 3.6+
    • future：必需（工具链的 Python 2/3 兼容层）
    • lxml：可选，用于 XML schema 校验（缺失时自动跳过校验并打印警告）
  • C 端编译生成产物：任意 C99 编译器（gcc/clang/交叉编译器）
  • C++ 端编译生成产物：支持 C++11 的编译器

构建

快速开始

构建流程：

  1. build.bash 切换到项目根目录，执行 python3 -m script.build
  2. script/build.py 计算构建指纹（入口 XML 内容 + language / wire_protocol 配置的 SHA256 组合哈希），与 script/xml.stamp 中的历史指纹比对：
    • 一致 → XML 与配置均无变化，跳过生成（增量构建）
    • 变化 → 调用 mavgen 重新生成，并更新 stamp
  3. 生成成功 → build/ 下产出各方言目录与运行时头文件

构建配置

在 script/build.py 顶部修改：

参数 当前值 说明
output build/ 产物输出目录
language c 生成 C 实现；改 c++11 生成 C++ 实现
wire_protocol 2.0 MAVLink 2.0 线协议（STX = 0xFD，24 位消息 ID）
validate True 按 mavschema.xsd 校验 XML

注意：切换入口 XML 后 build/ 不会自动清理，旧方言目录会残留。切换前建议手动清空 build/，避免误用过期产物。

生成流程概述

要点：

  • 入口与 include 链：mavgen 只处理入口 XML 及其 <include> 引入的文件。官方方言的继承链为 common.xml → standard.xml → minimal.xml，被引用文件必须位于 config/。
  • 字段重排序：MAVLink 按字段类型长度降序重排（对齐优化），线上字节序与 XML 书写顺序可能不同，生成代码已自动处理，无需关心。
  • CRC_EXTRA：每条消息由消息名 + 字段定义计算的额外校验种子，收发两端必须使用同一版本 XML 生成的代码，否则校验失败。
  • 重复检查：跨 include 链的消息 ID / 消息名 / 枚举值重复会在生成阶段报错终止。

XML 消息定义格式

编写要点：

  • 消息 ID：24 位（0 ~ 16777215），全局唯一；发布后不要随意变更，收发两端必须同版本
  • 字段类型：uint8_t / int16_t / uint32_t / int64_t / float / double / char，数组写 类型[N]
  • include 继承：<include>common.xml</include> 可继承基础方言；注意本项目 bms.xml 复用了标准消息 ID（如 75/77/111/147）做自定义内容，不能 include common.xml（会报 Duplicate message id）
  • 新版官方元素：官方新版 XML 的 <superseded>、field 的 minValue/maxValue/multiplier 已在 mavschema.xsd 中补齐支持
  • 保留字：消息/字段名不得使用各语言关键字（schema 校验会拦截）

高级特性

消息签名（MAVLink 2.0）

v2.0 支持基于 SHA-256 的消息签名（mavlink_sha256.h + mavlink_helpers.h），默认编入无需编译开关：

  • 按通道启用：将 mavlink_get_channel_status(chan)->signing 指向填好的 mavlink_signing_t（密钥、时间戳回调）
  • 方向控制：MAVLINK_SIGNING_FLAG_SIGN_OUTGOING 等标志位（见 mavlink_types.h）
  • 签名/验签在打包与解析路径中自动完成

跨平台配置宏

在 include mavlink.h 之前定义以下宏可裁剪/适配目标平台：

宏 默认 说明
MAVLINK_MAX_PAYLOAD_LEN 255 最大负载长度，内存受限设备可调小
MAVLINK_COMM_NUM_BUFFERS 4（无签名）/ 16（签名） 解析通道数，多路串口场景按需增大
MAVLINK_USE_CONVENIENCE_FUNCTIONS 未定义 定义后启用 *_send() 便捷函数（需自行提供 comm_send_ch()）
MAVLINK_LITTLE_ENDIAN 自动检测 大端平台需显式定义
MAVLINK_EXTERNAL_RX_STATUS 未定义 定义后接收状态由外部提供，适合多实例/RTOS 场景
MAVLINK_EXTERNAL_RX_BUFFER 未定义 定义后接收缓冲由外部提供（同上）

消息签名无编译开关，默认编入；按通道启用（见上文签名说明）。

测试生成代码

  • C++11 测试：script/CPP11/test/posix/（make 后运行 mtest）；方言目录的 gtestsuite.hpp 提供基于 Google Test 的逐消息序列化回环测试
  • C 自测：方言目录的 testsuite.h 为每条消息预置测试值，可嵌入目标工程做打包/解包回环验证

常见问题

现象 原因与处理
内容无变化，跳过生成 XML 与生成配置均未变化，属正常增量行为；强制重建删除 script/xml.stamp
Unsupported language xxx language 拼写错误；C 用 c，C++ 用 c++11（或 cpp11/CPP11）
C++ implementation only support --wire-protocol=2.0 C++ 生成仅支持 2.0 协议
Element 'superseded': This element is not expected mavschema.xsd 缺少新版元素定义，需补充（本项目已补，若文件被回退需重新补）
FileNotFoundError ... standard.xml/minimal.xml include 链基础文件缺失，从官方仓库 message_definitions/v1.0/ 下载到 config/
Duplicate message id include 链内消息 ID 冲突（如 bms.xml 不能 include common.xml）
Failed to import lxml 警告 未安装 lxml，校验自动跳过；pip3 install lxml
切换入口后 build/ 里有多余方言目录 build 不清理输出目录，属上次构建残留，手动清空 build/ 后重建
解析端一直 BAD_CRC 收发两端 XML 版本不一致导致 CRC_EXTRA 不匹配，需同版本重新生成

注意事项

  • 增量指纹覆盖 XML 内容 + language + wire_protocol；output 路径等其他参数变更不触发重建，必要时删除 script/xml.stamp
  • 官方方言三件套（common/standard/minimal.xml）更新时需从同一版本同步，避免定义不一致
